# dsh-game-hub · 游戏中心

> 一个悬浮在 DeepSeek Harness 右下角的游戏入口，装下 11 款游戏：
> 自研的《三国志》战略、《诺基亚弹珠台》街机，以及复刻的 9 款经典。

点开即玩，不占会话、不开新窗口、不起服务。

---

## 它是什么

DSH 里原本每个小游戏都是独立插件，各自挂一个悬浮按钮，装到第四个就摆不下了。
游戏中心把它们收进一张卡片墙：**一个按钮，11 款游戏，按类型分组**。

```
                     🎮 游戏中心（右下角）
                            ↓ 点开
        ┌─────────────────────────────────────┐
        │  战略   [三国志]                     │
        │  街机   [弹珠台] [小蜜蜂]             │
        │  经典   [贪吃蛇] [俄罗斯方块] [打砖块] │
        │         [扫雷]                        │
        │  休闲   [2048]                        │
        │  棋牌   [五子棋] [中国象棋] [掼蛋]     │
        └─────────────────────────────────────┘
                            ↓ 点一张卡
                    游戏占满面板，左上角「←」返回卡片墙
```

每张卡片右上角显示该游戏的历史最高分，存在 `localStorage` 里，前 10 名留榜。

## 安装

### 从 GitHub

```bash
dsh plugin install https://github.com/zhanghao3693/dsh-game-hub
```

### 从 npm

```bash
dsh plugin install @dpharness/dsh-game-hub
```

### 从本地目录（改代码时用这个）

```bash
git clone https://github.com/zhanghao3693/dsh-game-hub
cd dsh-game-hub
npm run build
dsh plugin install /绝对路径/dsh-game-hub
```

## 三个棋牌 AI 的实现

这部分是唯一需要「算」的地方，单独说。

### 五子棋：分层优先，不是加权和

最早写成 `自己的分 × 1.06 + 对手的分`，结果 AI 永远在堵、永远不成杀 —— 因为堵一个活四的收益永远高于自己做一个活四，二十局全和棋。

改成**分层判定**：

```js
mine ≥ FIVE       → 1e9 + mine    // 自己能成五，立刻赢
theirs ≥ FIVE     → 1e8 + theirs  // 对手能成五，必须堵
mine ≥ OPEN_FOUR  → 1e7 + mine    // 自己活四，必胜点
theirs ≥ OPEN_FOUR→ 1e6 + theirs  // 对手活四，必须堵
否则              → mine * 1.15 + theirs
```

档次差别不靠「搜索更深」而是靠**是否关闭双三/四三加成**：简单档看不见组合棋型，困难档才吃这套。

### 中国象棋：迭代加深，不是固定深度

固定 depth 4 的老实现在 1400ms 预算下会「算一半就被掐断」，然后把半层结果和算完的 depth 3 混着比 —— 困难档因此偶尔输给简单档。

改成**逐层加深**：

```js
for (let d = 2; d <= maxDepth; d += 1) {
  // 完整算完这一层才采纳，并把它排序后的结果作为下一层的起点
  // 某一层超时就 break，保留上一层的完整结果
}
```

搜索本身用 alpha-beta + 吃子价值排序，加「同分池随机」避免每局开局走法雷同。困难档单步实测 79–150ms。

### 掼蛋：完整规则，不是简化版

四人两队（对家是队友）、两副牌 108 张、级牌、**红桃级牌当逢人配**、进贡还贡、抗贡。

牌型覆盖单张/对/三/三带二/顺子(5)/连对(3 对)/钢板(2 个连续三张)/同花顺/4–8 张炸弹/四大天王。

几个容易写错、实测复现过并修掉的坑：

| 坑 | 现象 | 原因 |
|---|---|---|
| 连对永远识别不出来 | 出连对报「牌型不合法」 | 判据用了「不同点数个数」去比 6，永远是 3 |
| 先手必胜 | 20 局 20 胜 | `leadSeat` 只在出完牌时才更新，开局那个人永远拿回牌权 |
| 抗贡永不触发 | 进贡率 100% | 用上一局**已打空**的手牌判抗贡，而不是本局新摸到的牌 |
| 打 A 一赢就通关 | 升级曲线失真 | 真规则是打 A 必须双下才能通关 |

修完后连打 40 局：0 卡死、牌数守恒、先手胜率 10:10 / 13:7 / 9:11 / 12:8。

## 面板里的两个老游戏怎么搬进来的

三国志和弹珠台分别有 2149 行和 1053 行，都是实测调过参的老代码，重写等于扔掉验证过的数值。

做法是**保留正文，只切三刀**（`tools/import-legacy.mjs`）：

1. `ThreeKingdomsOverlay` → `ThreeKingdomsGame({ onExit })`
2. `useState(false)` → `useState(true)` —— 让旧的「收起状态只渲染 FAB」分支变成不可达死代码，旧按钮自动消失，且不用删一行 JSX
3. 关闭按钮的 `setOpen(false)` → `onExit()`

正文两侧的 `window.__ModuleLoader__.load()` 包装和插件注册段剥掉，改由游戏中心统一提供外壳。

存档 key 保持原样（`dsh.three-kingdoms.save.v1`），旧的进度不受影响。

## 结构

```
src/
  core/
    registry.js   游戏注册表：defineGame / allGames / gameById
    util.js       存档、高分榜、随机数、命中检测
    ui.js         游戏通用件：useKeys / useLoop / GameChrome / useFitCanvas
  games/          九款自研游戏，文件名前缀即显示顺序
  legacy/         两台老游戏（自动生成，勿手改）
  shell/
    50-register.js  登记迁入的两款游戏
    90-shell.js     卡片墙 + 面板 + 返回逻辑
    99-entry.js     插件出口，注册 shell.overlay 槽位
tools/
  import-legacy.mjs  从旧插件抽正文
  build.mjs          按 core→games→legacy→shell 拼接成单文件
  test.mjs           166 项断言
```

**为什么不用打包器**：DSH 宿主只认一个 `factory`，没有跨文件 import 通道。所有源码按顺序拼进一个 `window.__ModuleLoader__.load({ id, factory })` 就够了，加 esbuild 只为一个字符串拼接不值当。

## 开发

```bash
npm run build   # 重新生成 dist/client.js
npm test        # 166 项断言
```

`npm test` 用 vm 沙箱跑 `factory`，不需要浏览器：

- 三国内核：开局八城、调将每月一次、`endTurn` 复位、`aiTurn` 跑一月不崩
- 弹珠台：发球后球动、左翻板能摆动
- 九款自研游戏：牌型识别、碰撞、搜索、AI 决策
- 组件渲染冒烟：11 个组件都在假 React 下构建界面树

**渲染冒烟抓出过两个会直接打不开游戏的 bug**：贪吃蛇的 `useLoop` 写在 `const draw` 声明之前（暂时性死区，一进游戏就崩），以及游戏通用 CSS 从未注入页面（所有内置游戏布局全死）。纯逻辑测试抓不到这两类。
